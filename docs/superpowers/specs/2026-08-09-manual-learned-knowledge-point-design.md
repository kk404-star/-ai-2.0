# 知识点手动标记已学设计

## 目标

让学生在知识点目录中保留正常进入 AI 学习的路径，同时允许已经在学校学过该知识点的学生主动标记为“已学习”，随后直接进入练习巩固。

## 入口与双路径

- “未学习”和“学习中”的知识点卡片主体继续进入现有知识点学习页。
- 同一卡片增加独立的“标记已学”按钮；点击按钮不得触发卡片主体的学习跳转。
- “已学习”的知识点不再显示“标记已学”，显示“去练习”。
- “已练习”的知识点保持现有完成状态和后续练习入口，不允许降级为“已学习”。

## 确认弹窗

- 点击“标记已学”后显示居中确认弹窗和遮罩。
- 标题为“确认标记为已学？”；内容卡展示知识点标题、学科和所属章节。
- 主按钮为“确认标记”，使用现有翡翠绿主色。
- 次按钮为“取消”，关闭弹窗且不改变知识点状态。
- 点击遮罩不提交状态，避免误操作；可关闭弹窗。

## 成功反馈与练习

- 确认后将知识树中对应知识点的 `masteryState` 更新为“已学习”。
- 成功弹窗复用同一遮罩层，展示绿色勾选图标、标题“已标记为已学”和知识点信息。
- 主按钮为“去练习巩固”，直接进入该知识点对应的现有练习流程。
- 次按钮为“稍后再说”，关闭弹窗并停留在知识点目录；该知识点立即显示为“已学习”和“去练习”。
- 若知识点在弹窗打开期间已变为“已学习”或“已练习”，确认操作保持幂等，不覆盖更高状态。

## 数据与组件边界

- `App` 继续作为知识树状态的唯一所有者，提供 `onMarkKnowledgeAsLearned(code)` 回调。
- `StudyView` 管理当前待确认知识点与弹窗阶段，不复制知识树数据。
- 弹窗使用知识树已经包含的标题、学科、章节和代码，不新增后端接口。
- 当前演示数据的状态仍为会话内状态；本次不新增账号级服务端持久化。

## 视觉规范

- 严格沿用项目 `DESIGN_SYSTEM.md`：翡翠绿主色、白色卡片、浅灰背景、16px 主卡圆角、12px 按钮圆角和轻阴影。
- 不采用参考图中的蓝色按钮。
- 弹窗适配 390px 手机容器，按钮使用足够的点击高度，长知识点名称允许两行。
- 状态变化使用短暂、轻量的反馈，不增加持续性装饰动画。

## 验收标准

- 未学习或学习中的知识点可以正常进入学习页。
- 点击“标记已学”只打开确认弹窗，不进入学习页。
- 取消后状态不变。
- 确认后知识点状态变为“已学习”，目录操作变为“去练习”。
- 成功弹窗的“去练习巩固”进入正确知识点练习。
- “稍后再说”停留在目录并保留已学习状态。
- 已练习状态不会被手动标记操作降级。
- 390px 宽度无横向溢出，TypeScript 检查、自动测试、生产构建和 GitHub Pages 部署通过。

## 本次范围外

- 不新增后端学习记录接口或跨设备同步。
- 不修改 AI 学习对话、题目判定和练习完成规则。
